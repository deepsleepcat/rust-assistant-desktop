## 本章目标

素材问题经常伪装成配置问题：单位加载失败看似是炮塔键错误，实际是图像不存在；地图预览能看，实战加载却找不到 TSX；英文文本正常，中文显示为空；声音字段没有报错，却因为解码失败静默退回。编码代理必须把“一个引用字符串”当作一个有字段上下文、路径根、格式约束、生命周期和发布依赖的对象。

本章建立四件事：

1. 一个字段能接受什么形式的素材或特殊值；
2. 一个相对路径从哪里解析，能否跨到根、共享或核心资源；
3. 一个本地化值如何回退、何时动态求值；
4. 一张 TMX 地图从预览到实际部署还依赖哪些文件。

静态目录存在不等于引擎可加载；预览图能显示不等于地图可部署；播放器能播放不等于游戏解码器可用。最终必须在目标游戏、目标版本和最终 `.rwmod` 中验证。

## 一、素材引用的通用模型

### 1. 每个引用先回答五个问题

遇到 `image`、`image_turret`、`iconImage`、`Image`、`shoot_sound`、地图缩略图、语言键或 tileset 路径时，不要只问“文件在不在”。先填写下表：

| 问题 | 需要确定的内容 | 失败的典型表现 |
|---|---|---|
| 字段上下文 | 当前键允许图片、声音、内建名称还是特殊前缀？ | 把 `NONE` 填入只接受图片的键 |
| 解析根 | 本地相对、`ROOT:`、`CORE:`、`SHARED:` 中的哪一种？ | 在错误根下出现“文件不存在” |
| 格式 | 扩展名、编码、帧数、透明度、音频解码能力 | 文件可打开但游戏加载失败或回退 |
| 运行时语义 | 是主体图、阴影、图标、投射物、效果、音乐还是 TMX 外部依赖？ | 素材存在但绘制层或触发时机错误 |
| 打包可达性 | 最终 ZIP 内是否有相同相对路径和所有间接依赖？ | 开发目录可用，`.rwmod` 内失效 |

“路径”必须和“字段”一起审阅。某些字段接受 `NONE`、`SHADOW:`、`SHARED:`、`CORE:` 或 `ROOT:` 一类特殊记号，另一些字段不接受。不能因为某个字段支持某个前缀或 `NONE`，就把它推广到所有图片、声音或地图字段。

### 2. 路径根与安全边界

通常优先使用相对当前模组文件的局部路径。字段支持时，可以使用下列前缀指向特定根：

| 形式 | 设计意图 | 使用时必须核验 |
|---|---|---|
| `assets/unit.png` | 模组内相对资源 | 相对位置、大小写、最终压缩包位置 |
| `ROOT:assets/unit.png` | 模组根目录相对资源 | 当前字段确实支持该前缀；路径位于根内 |
| `CORE:...` | 游戏核心资源 | 目标版本存在该资源；不把它当成模组内部文件 |
| `SHARED:...` | 引擎或共享资源路径 | 字段支持性、目标版本和分发可用性 |
| `SHADOW:...` | 某些图像字段的阴影语义 | 仅在该字段的语义中使用，确认不是普通路径 |
| `NONE` | 某些字段的禁用语义 | 确认该字段允许，不要拿来代替缺文件 |

路径不得逃离模组根。任何通过 `..`、盘符、网络路径、符号链接假设或压缩包条目技巧访问根外内容的方案都不应进入模组。它既不可靠，也破坏可再现打包：开发者机器偶然存在的文件不可能成为发布依赖。

建议将模组自有素材集中在清晰目录，例如 `assets/images/`、`assets/audio/`、`maps/`、`locale/`。这不是引擎强制目录，而是降低相对路径歧义的工程约定。若已有项目布局不同，优先遵循已有布局并补齐索引，而不是仅为美观进行大规模移动。

### 3. 路径规范化检查

代理可在打包前做“字符串到归档条目”的映射审计：

1. 收集所有已知素材字段中的引用值。
2. 区分内建名称、特殊前缀、本地路径和无效空值。
3. 针对本地路径按字段所在文件或模组根解析。
4. 规范化分隔符，拒绝跳出根目录的结果。
5. 检查磁盘存在、大小写一致、不是目录。
6. 在最终 ZIP 中检查同名条目存在。
7. 对地图进一步递归到 TSX、图块和对象模板等间接依赖。

这只能发现路径层问题。图片破损、帧尺寸错误、音频解码不兼容、字段不支持该前缀仍需引擎验证。

## 二、图像：从文件存在到正确绘制

### 1. 主体图不是可选装饰

单位的 `[graphics]` 中需要可加载的主体 `image`。图像加载失败是致命问题；不能指望游戏以透明占位图继续运行。开始排错时先确认最短链路：单位文件加载、`[graphics]` 存在、`image` 指向的文件在包中、图片由目标运行环境可读。

最小的示意结构如下，文件名和尺寸均为新写的占位例子：

```ini
[graphics]
image: assets/images/signal_pylon.png
total_frames: 1
teamColoringMode: disabled
```

这段示例不声称所有单位都只需这三个键；它只表明主体资源、帧数和队伍着色策略是应显式审阅的基本面。不要拿样本模组的贴图、帧布局或色板直接复制为“默认答案”。

### 2. 帧数和图集

`total_frames` 至少必须为 `1`。将它设为零、负数、空字符串，或让声明帧数与图集实际布局矛盾，都会使图像解析或绘制行为不可靠。对每张多帧图建立元数据记录：

| 字段 | 建议记录 |
|---|---|
| 文件 | 相对根的稳定路径 |
| 像素尺寸 | 宽、高 |
| 布局 | 横向、纵向、网格或由字段定义的 stride |
| 帧数 | `total_frames` 的值与推导理由 |
| 单帧尺寸 | 若显式设置 `frame_width`/`frame_height`，记录二者 |
| 透明边距 | 是否故意存在，避免“画面偏移”误判 |
| 用途 | 主体、炮塔、阴影、效果、投射物或 UI 图标 |

一个常见失败是原图从单帧改成条带图，却忘了同步 `total_frames`；另一个是把 UI 图标当成单位主图，缩放后碰撞与视觉中心不一致。配置本身不能替代素材规格。

### 3. 队伍着色是兼容矩阵，不是二选一偏好

`teamColoringMode` 的有效值包括 `pureGreen`、`hueAdd`、`hueShift` 和 `disabled`。`teamColorsUseHue` 与某些 `teamColoringMode` 组合不兼容，会被加载器拒绝。不要为了兼容旧写法同时写多个相互冲突的键。

| 目标 | 合理思路 | 必测风险 |
|---|---|---|
| 完全不染色 | 显式 `disabled` | 是否仍有其他炮塔或图标染色字段 |
| 以纯绿色像素作为队色掩码 | 选择匹配语义的模式并按素材规则制图 | 边缘抗锯齿、半透明绿色、非预期区域被染色 |
| 使用色相类模式 | 明确选 `hueAdd` 或 `hueShift` | 与 `teamColorsUseHue` 的组合是否合法 |
| 炮塔单独染色 | 检查炮塔图像字段和应用队色字段 | 主体、炮塔、阴影的颜色策略不一致 |

工程原则是“一张素材，一种已文档化的染色意图”。把同一张图在不同单位上用不同模式不是绝对禁止，但必须在视觉回归中逐色检查。不要把纯绿色以外的装饰色放进可能被掩码处理的像素区。

### 4. 阴影、特殊记号与字段感知

`image_shadow`、效果图、投射物图、图标图和主体图的可接受值不必相同。`NONE` 可能是某些字段的合法禁用值；`SHADOW:` 可能只在特定阴影语义中有意义；`CORE:`、`SHARED:`、`ROOT:` 是否可用也取决于解析该键的代码路径。以下表格是审阅规则，而不是允许值大全：

| 场景 | 代理应当做什么 | 不应当做什么 |
|---|---|---|
| 不需要阴影 | 查 `image_shadow` 的字段语义后使用其允许的禁用形式 | 用空路径或随意填 `NONE` |
| 想使用内建资源 | 确认具体图片字段支持 `CORE:` 或 `SHARED:` | 仅凭其他字段成功过就套用 |
| 想引用模组根图片 | 确认当前字段支持 `ROOT:` | 用 `../` 穿出当前目录猜测根 |
| 想生成阴影 | 使用该字段允许的 `SHADOW:` 或独立阴影图方案 | 在普通 `image` 中写阴影标记 |
| 图片不显示 | 同时检查文件、字段、图层、可见 LogicBoolean、帧和大小 | 只换路径并忽略其它配置 |

### 5. 图像资产验收矩阵

| 检查层 | 检查项 | 合格证据 |
|---|---|---|
| 文件层 | 文件存在、不是零字节、名称一致 | 打包前清单与归档条目一致 |
| 解码层 | 目标运行时能读取格式 | 游戏加载无图像异常 |
| 配置层 | 必需 `[graphics]image`、`total_frames >= 1`、字段合法 | 单位扫描完成 |
| 视觉层 | 方向、帧、阴影、队色、缩放正确 | 游戏内截图或人工核对 |
| 规模层 | 批量单位、缩放、远距离视图仍合理 | 性能与 UI 复测 |

## 三、音效与音乐：文件、内建名、解码和节制

### 1. 声音字段的两种来源

声音引用可能是内建声音名，也可能是模组文件。作为文件时，扩展名必须是 `.ogg` 或 `.wav`。没有扩展名的值可能被解释为内建声音，而不是待查找的文件。因此，一个名为 `alert` 的裸值和 `assets/audio/alert.ogg` 的含义不同，不能靠“它碰巧在开发机响了”判断。

| 写法 | 应按什么审阅 | 常见误解 |
|---|---|---|
| `warning` | 视为可能的内建名，核对目标版本 | 以为会自动寻找 `warning.ogg` |
| `assets/audio/alert.ogg` | 文件存在、扩展名、压缩包位置、解码 | 只检查文件扩展名 |
| `assets/audio/alert.wav` | 同上，额外测试目标设备的解码 | 用桌面播放器成功替代引擎测试 |
| 没有文件扩展名的自定义名 | 不依赖其解析为外部文件 | 让发布包出现不可预测回退 |

若音频解码失败，引擎可能给出警告并使用回退路径。警告不是无关紧要的“可选优化”：回退会改变玩家反馈，且不同设备、版本或打包状态可能表现不同。把所有音频警告视为发布阻断项，直到证明该字段设计上确实应使用内建名。

### 2. 声音事件设计

声音是状态机副作用，应区分听众和频率。单个单位的开火音、面向玩家的确认音、面向全局的事件声不应混用。

| 事件 | 推荐听众语义 | 频率控制 |
|---|---|---|
| 选中与移动命令 | 本地发令玩家 | 连续命令时避免叠加 |
| 单位开火 | 单位附近或战场语义 | 高射速需节流或使用轻量素材 |
| 状态切换成功 | 发起玩家 | 一次提交只响一次 |
| 全局胜负或大型事件 | 全体受影响玩家 | 不由每个单位分别触发 |
| 调试状态 | 开发者本地 | 正式版不应持续触发 |

对多单位群集最危险的是“每个单位每帧或每次低冷却触发完整音效”。这会造成混响、性能和反馈噪声三重问题。先设计声音预算：同类事件单位数量翻十倍时，听感和性能是否仍可接受？

### 3. 自有音频的最小登记表

| 字段 | 内容 |
|---|---|
| 逻辑 ID | 例如 `sound_pulse_start`，不是玩家翻译文本 |
| 物理路径 | `assets/audio/pulse_start.ogg` |
| 调用点 | action、turret、effect、死亡或地图音乐 |
| 听众 | 单位、己方玩家或全局 |
| 最大频率 | 每次动作、每秒上限或冷却 |
| 回退 | 是有意使用内建名，还是解码失败即阻断发布 |
| 许可 | 自有、明确授权或可再分发来源 |

音频文件本身也属于发布资产。不要把编辑工程源、未压缩母带、许可证不清的试听文件和多个“final_final”版本一并塞入 `.rwmod`。

### 4. 地图音乐

地图或模组音乐设置会涉及 `sourceFolder`、是否 `exclusive`、是否 `addToNormalPlaylist` 等控制。`.ogg` 文件会被发现，但“被发现”不等于“符合场景意图”。

| 目标 | 需要确认 |
|---|---|
| 专属地图音乐 | 目录、曲目、独占策略、地图加载后的实际播放 |
| 加入普通播放列表 | `addToNormalPlaylist` 语义、不会把测试素材发布给所有局 |
| 只在特定内容包可用 | 打包内路径和相应开关完整存在 |
| 避免重复 | 同一曲目没有同时以多个路径或多个清单登记 |

“预览页面能播放”不能证明游戏的音乐扫描和场景选择正确。必须从最终归档安装，进入实际地图并切换多个场景验证。

## 四、本地化：值、键、回退和动态文本

### 1. 两种本地化入口

单位和行动文本可以使用直接 locale 值，如 `displayText`、`displayDescription` 及其 `_zh`、`_en` 变体；也可以使用 `i:` 映射到游戏翻译键。它们解决的问题不同：直接值适合与配置同处、变更小的文本；翻译键适合多处复用、由独立 locale 文件统一维护的术语。

| 方式 | 示例意图 | 适合 | 风险 |
|---|---|---|---|
| 直接默认值 | `displayText: 信号塔` | 单一默认语言、少量短文本 | 重复词汇漂移 |
| 直接语言覆盖 | `displayText_zh: 信号塔`、`displayText_en: Signal Pylon` | 需要紧邻单位阅读 | 漏某一语言时回退不符合预期 |
| `i:` 翻译键 | `displayText: i:units.signal_pylon.name` | 名称、术语、跨单位一致性 | 键不存在、拼写不一致或包内 locale 缺失 |
| 动态插值 | `text: 储备 %{...}` | 运行时数值状态 | 表达式类型、性能、文本长度 |

不要把玩家可见的中文直接嵌入逻辑 ID，也不要让同一个键在不同文件中表达互相矛盾的概念。先建立“概念 ID -> 各语言值 -> 使用位置”的小表，尤其是单位名、升级名、锁定原因、地图名、作者信息和版本提示。

### 2. 回退规则必须主动测试

locale 会先尝试精确语言，再尝试去掉区域部分后的默认语言。例如请求的地区语言不一定有专门条目时，需要验证它会落到无区域的值还是直接回到基础文本。不要凭直觉认为 `zh-CN`、`zh_cn`、`zh` 的表现完全相同；按目标版本、实际键和 UI 场景测试。

建议覆盖以下用例：

| 当前游戏语言 | 包内值组合 | 预期要核对 |
|---|---|---|
| `zh` | `_zh` + 默认 | 是否优先中文 |
| `zh-CN` 或等价区域语言 | `_zh` + 默认 | 是否按无区域中文回退 |
| `en` | `_en` + 默认 | 是否优先英文 |
| 未翻译语言 | 仅默认 | 默认值是否可理解、是否显示键名 |
| 区域专用语言 | 区域条目 + 无区域条目 | 精确条目是否优先 |

回退正确不代表翻译质量正确。术语、按钮长度、换行、占位符和玩家语气仍需人工校对。避免把内部实现名、资源 ID、调试状态和未完成标记暴露为正式 UI 文本。

### 3. `displayLocaleKey` 与全局单位翻译

`displayLocaleKey` 有全局单位翻译回退。它有利于让同一单位概念维持一致，也意味着它可能掩盖本地文件中遗漏的显示文本。审阅时区分两件事：

1. 当前值是否成功从全局单位翻译取得回退；
2. 模组是否有意依赖该回退，且目标版本和发布场景一定存在它。

若模组要独立发布且文字是玩法说明，不能只依赖一个隐含的全局回退来保证可理解。至少为关键名称、描述和锁定原因提供本模组可控的默认值或已验证翻译键。

### 4. 动态 `%{logicBoolean}` 的边界

`%{logicBoolean}` 在运行时重新求值，适合显示资源、阶段、充能、简单状态或目标信息。它不是构建期模板，也不应承担复杂搜索、随机副作用或未定义引用的容错。

```ini
[action_info_reserve]
displayType: infoOnly
text: 能量储备 %{self.resource(type='charge')}
text_zh: 能量储备 %{self.resource(type='charge')}
text_en: Charge %{self.resource(type='charge')}
```

这是新写的最小示意，不依赖任何第三方配置。实际实现前必须确认资源定义、表达式返回类型、语言键格式和 UI 宽度。动态值要满足以下约束：

- 只读取当前单位或已缓存的廉价状态；
- 缺失或空引用时有明确安全表现；
- 各语言的词序与数值单位自然；
- 文本不会在窄按钮、信息框或缩放界面中遮挡；
- 不把动态文本当作规则状态的唯一观测，关键玩法还要有 UI 状态或行为证据。

### 5. 本地化审阅清单

- [ ] 每个玩家可见的新概念有稳定键或直接默认值。
- [ ] 直接 `_zh`、`_en` 覆盖和 `i:` 的使用边界一致。
- [ ] 精确语言、无区域语言和未翻译语言都进行回退测试。
- [ ] `displayLocaleKey` 的全局回退不是独立发布时唯一依赖。
- [ ] 动态 `%{...}` 在目标单位状态、空状态和密集单位场景都可读。
- [ ] 锁定原因、价格单位、倒计时和提示语和实际规则一致。
- [ ] 不存在调试文本、硬编码路径、内部变量名或未经翻译的键名。

## 五、地图：TMX 是依赖图，不是一张预览图

### 1. 地图发现的前提

加载器只在允许模组地图的情况下注册 `.tmx`。因此“TMX 已打入包中”与“玩家能在地图列表看到它”之间还隔着模组加载设置、地图扫描位置、清单配置和游戏运行上下文。不要把目录浏览器里的文件存在当成地图已注册的证明。

源模组中可见 `[maps]` 的 `sourceFolder` 与 `addExtraMapsForPath` 一类模式。这些是可供审计的真实配置形态，不是所有项目都应照抄的目录设计。新模组应选择一套简单、可在最终包内验证的路径策略，并记录地图根目录。

| 层 | 需要验证 | 不能由什么替代 |
|---|---|---|
| 文件扫描 | `.tmx` 位于预期扫描目录，模组地图功能允许 | 文件资源管理器预览 |
| 配置登记 | `[maps]` 指向正确目录或额外路径 | 其他模组的 `sourceFolder` 写法 |
| 地图解析 | TMX XML、层、对象、tileset 合法 | 仅显示缩略图 |
| 依赖可达 | TSX、位图、模板、音乐都在包内 | 开发机上已有源文件 |
| 实战运行 | 进入房间、加载、生成、重新开始、多人场景正确 | 单次编辑器打开 |

### 2. TMX 依赖链

TMX 可以内嵌 tileset，也可以通过外部 TSX 继续引用图块位图；还可能关联对象模板、图像层、属性资源和预览图。应当把每张地图当作一个根节点，递归收集它的依赖。最小图可表示为：

`地图.tmx -> 地形.tsx -> terrain.png`

真实地图常比这个长。外部 TSX 的相对路径通常以 TMX 或 TSX 所在位置为上下文解析；代理不可将字符串简单地统一按模组根拼接。必须逐边解析、规范化并验证最终归档中有对应条目。

| 依赖类型 | 从哪里发现 | 应验证什么 |
|---|---|---|
| 外部 TSX | TMX 中的 tileset source | 文件存在、路径相对基准、归档条目 |
| 图块位图 | TSX 或内嵌 tileset image source | 图像存在、尺寸可读、透明和路径正确 |
| 图像层 | TMX 图像层 source | 相对路径、裁剪与显示层次 |
| 对象模板 | TMX 对象模板引用 | 模板文件和它的二级资源 |
| 自定义属性 | TMX/TSX/对象属性 | 单位或脚本引用在目标包可解析 |
| 地图缩略图 | metadata 相关相对路径 | 路径相对性、尺寸和打包存在 |
| 音乐目录 | maps 或音乐配置 | `.ogg` 发现和运行时播放 |

对来自两个 DeepStar 模组的地图观察到 TMX、预览 PNG 与 TSX 引用的组合。这一事实只说明“预览 PNG + TMX”不足以证明可部署；TSX 与其位图必须沿源链验证。不得复制其中地图、tileset 或作者素材。

### 3. 地图元数据和缩略图

地图 metadata 的缩略图通常为相对路径。路径的相对基准、是否允许前缀、是否会在 ZIP 中保留同样层级都需要单独验证。缩略图可见只证明 metadata 到 PNG 的一段成功，不证明 TMX 到 TSX、TSX 到图块、地图中的单位引用或音乐配置可用。

缩略图验收应覆盖：

- 文件真实存在且在最终归档的同一路径；
- 名称与大小写匹配；
- 它确实代表当前地图版本，而非旧导出；
- 在地图选择界面显示不变形、不透明遮挡、不指向别的地图；
- 删除开发目录源文件后，从 `.rwmod` 仍能显示。

### 4. 地图内容与单位引用

地图可能通过对象、属性或起始布置引用单位。单位本身又可能通过 `copyFrom`、`overrideAndReplace`、`canBuild`、`builtFrom` 和升级关系形成加载后依赖。因此地图验证不能只停留在 XML 正确：它还必须在当前模组启用状态下创建地图所需单位。

建议建立“地图测试档案”：

| 场景 | 最少执行步骤 | 应观察 |
|---|---|---|
| 初次发现 | 在地图列表筛选或浏览 | 名称、缩略图、描述可见 |
| 首次加载 | 单人进入并等待初始化 | 无缺 tileset、单位或资源错误 |
| 重开 | 重新开始相同地图 | 初始化无重复生成或状态残留 |
| 多队伍 | 选择不同队伍或 AI | 起始点、阵营物件、胜负条件正确 |
| 放大缩小 | 浏览图块、图像层和边缘 | 无黑块、错位、透明异常 |
| 最终包 | 删除或避开开发目录，安装 `.rwmod` | 与源目录测试一致 |

### 5. 地图音乐与正常播放列表

对地图音乐要明确是否为专属、是否独占、是否加入普通播放列表。`sourceFolder`、`exclusive` 与 `addToNormalPlaylist` 描述的是不同层面的行为，不能只因曲目被扫描到就认为策略正确。

| 策略 | 应有的文档化意图 | 回归风险 |
|---|---|---|
| 专属并独占 | 某张地图或场景必须使用特定曲目 | 切离地图后仍错误播放 |
| 专属但不独占 | 曲目可与正常逻辑共存 | 多曲叠加或优先级意外 |
| 加入普通列表 | 模组希望全局增加可选曲目 | 测试曲或无许可音乐泄漏到普通局 |
| 不提供音乐 | 依赖游戏默认 | 不应保留无用目录与错误登记 |

音乐必须在最终包中实际加载和切图测试。因为 `.ogg` 被发现与正确的选择、解码、音量和独占行为是不同层的验证。

## 六、资源树的工程组织

### 1. 推荐的可审计布局

以下只是示意布局，项目可按已有规范调整。重点是依赖路径短、所有权清楚、导出物与源文件分离：

```text
mod-root/
  assets/
    images/
    audio/
  locale/
  maps/
    previews/
    tilesets/
  units/
  mod-info.txt
```

不要把 Photoshop、音频工程、缓存缩略图、导出中间帧和源控制元数据放进发布根。发布层只保留引擎加载所需的最终资源和经过审阅的许可信息。

### 2. 素材 ID 与文件名

建议文件名使用稳定 ASCII、小写、下划线或短横线，并避免空格、重复扩展名、仅大小写差异、操作系统保留名和“新建文件 (2)”一类临时名。原因不是游戏一定拒绝所有这些形式，而是 ZIP、跨平台文件系统和人工审阅容易出现歧义。

| 不佳命名 | 问题 | 改进方向 |
|---|---|---|
| `最终版.png` | 跨工具处理与版本语义混合 | `signal_pylon.png` |
| `gun.PNG` 与 `gun.png` | 大小写敏感环境冲突 | 保留唯一小写名 |
| `laser (1).ogg` | 复制残留，引用容易指错 | `laser_charge.ogg` |
| `map-preview-new-new.png` | 名称不表达绑定地图 | `valley_preview.png` |
| `tileset.psd` | 不是发布运行时素材 | 在源工程外保存 |

## 七、编码代理的实施工作流

### 新增或替换图像

1. 确认目标字段、单位节和当前图像语义。
2. 选择模组内相对路径；只有字段明确支持时才用 `ROOT:`、`CORE:`、`SHARED:` 或 `SHADOW:`。
3. 写入主体图时确保 `[graphics]image` 存在，`total_frames >= 1`。
4. 明确队伍着色模式，不混用与 `teamColorsUseHue` 不兼容的组合。
5. 在源树和最终 ZIP 中检查路径、大小写、帧数和依赖。
6. 在游戏内检查主体、炮塔、阴影、缩放、队色、远距离 UI。

### 新增声音或音乐

1. 决定它是内建声音名还是自有 `.ogg`/`.wav` 文件。
2. 对文件检查扩展名、解码、许可、归档路径和实际调用。
3. 指定听众和频率，避免单位群集时重复轰鸣。
4. 对地图音乐明确 `sourceFolder`、独占与普通列表策略。
5. 从最终包安装后进入实际场景验证，不以桌面播放器为准。

### 新增本地化

1. 为概念确定稳定键或直接默认值，避免逻辑 ID 充当展示文字。
2. 在 `_zh`、`_en`、默认值和 `i:` 之间选择一致策略。
3. 测试精确语言、无区域回退、未翻译语言和 `displayLocaleKey` 回退。
4. 检查动态 `%{logicBoolean}` 的类型、性能、空值和文本布局。
5. 比对 UI 文本和实际规则、价格、锁定条件。

### 新增地图

1. 确认模组地图允许、扫描目录和 `[maps]` 策略。
2. 从每个 TMX 递归解析 TSX、位图、模板、图像层、缩略图和音乐。
3. 将所有依赖写入归档验证清单。
4. 在源目录、干净安装和最终 `.rwmod` 中分别加载。
5. 测试重开、队伍变化、AI、缩放、边缘、地图音乐和缺失文件错误。
6. 把结果接入 [06-交叉引用、验证与调试](06-cross-references-validation-and-debugging.md) 的分层审计。

- [ ] 队伍着色模式有效，未与 `teamColorsUseHue` 形成不兼容组合。

- [ ] 默认文本、中文、英文、翻译键、地区回退和动态值都已测试。

### 地图

## 九、素材契约、依赖索引与变更影响

### 1. 为每项发布素材建立契约

素材契约不是把二进制文件复制进清单，而是说明该文件为何存在、可被什么字段使用、替换时必须维持哪些性质。它能防止“新图片路径正确但帧布局错了”“替换音频后群集时过载”“同名缩略图误指另一张地图”等问题。

| 契约字段 | 图片示例 | 音频示例 | 地图/TSX 示例 |
|---|---|---|---|
| 逻辑用途 | 单位主体、炮塔、效果或图标 | 开火、确认、死亡或地图音乐 | 地图本体、图块定义或预览 |
| 物理路径 | 根内相对路径 | `.ogg`/`.wav` 的根内路径 | TMX 相对 TSX，TSX 相对位图 |
| 调用方 | 单位节、效果节、行动 | turret/action/effect/maps | `[maps]`、TMX tileset、metadata |
| 格式约束 | 帧数、尺寸、透明、队色意图 | 扩展名、解码、音量、频率 | XML 可读性、相对路径、图块尺寸 |
| 运行时约束 | 图层、缩放、颜色模式 | 听众、重叠、回退 | 扫描条件、生成、重开行为 |
| 发布约束 | ZIP 条目、许可、无源工程 | ZIP 条目、许可、无母带 | 全部二级依赖和作者许可 |

替换素材前先比对旧契约和新契约。若只是像素优化，路径、帧数、队色策略和透明边距仍可能是兼容接口；若要改变这些接口，应将变更视为配置和视觉双重回归，而不是简单文件替换。

### 2. 资产依赖索引的维护方法

不必手写一个永远准确的大表，但每次变更要能回答“谁引用它”和“它又引用什么”。建议从以下三种入口采集：

1. 配置字段扫描：图片、声音、图标、效果、locale、地图和音乐设置中的字面路径或内建名；
2. 地图 XML 扫描：TMX 的 TSX、图像层、对象模板与 preview 相关引用；
3. 归档反向检查：最终 ZIP 中每个发布资源是否至少有一个已知用途，例外需标注为引擎扫描目录内容。

| 变更对象 | 必做正向检查 | 必做反向检查 |
|---|---|---|
| 主体 PNG | 图片字段、帧、队色、归档 | 哪些单位、模板、图标复用它 |
| 音频文件 | 调用点、扩展名、解码、频率 | 是否还有旧路径或重复副本 |
| locale 键 | 各语言值、回退、动态参数 | 哪些单位/行动/metadata 显示它 |
| TMX | 外部 TSX、图块、预览、音乐 | maps 配置与地图选择入口 |
| TSX | 位图、图块大小、相对路径 | 哪些 TMX 共用它 |
| 地图预览 | metadata 的相对路径、缩放 | 是否被另一张地图误复用 |

反向检查尤其重要：删除“未引用”图片之前，要排除 TMX/TSX 的二级引用、缩略图、动态扫描目录和未在简单 INI 搜索中出现的资源。反之，新增文件不被引用也可能是漏写配置或废弃导出物。

### 3. 图像替换的视觉回归脚本

对单位图片，建议按固定截图或观察顺序检查，避免只在一个角度确认：

1. 默认创建时的主体、方向、阴影和选择圈；
2. 不同队伍颜色下的主体、炮塔、图标和效果；
3. 建造中、低血量、开火、受击、死亡和转换状态；
4. 远距离缩放与小地图/缩略图语义；
5. 多帧图的首帧、末帧、循环交界与尺寸对齐；
6. 与地形、雾、液体、空中高度和其它单位的层级关系；
7. 最终 `.rwmod` 与源目录中是否一致。

| 视觉症状 | 常见根因 | 先检查 |
|---|---|---|
| 图像左上角偏移 | 透明边距、帧宽高、原点差异 | 图集规格与 offset 字段 |
| 旋转后错帧 | `total_frames` 或方向 stride 不匹配 | 帧布局和 graphics 方向配置 |
| 队色染到装饰 | 色板或模式不匹配 | `teamColoringMode` 与素材掩码 |
| 阴影出现在主体之上 | 错字段、图层或特殊标记误用 | 阴影字段语义和绘制层 |
| 远景消失或模糊 | icon、缩放、帧尺寸或透明度 | zoomed-out 资源和缩放策略 |
| 仅打包后缺图 | 路径基准、大小写、漏入 ZIP | 归档条目与字段路径 |

截图是证据，不是唯一标准。若图像在视觉上“差不多”，但帧数、队色或路径违反契约，后续版本或其它场景仍可能失败。

### 4. 音频的听觉回归与许可边界

音频回归不能只问“能否发声”。应测试声音是否在正确时机、正确听众、正确频率出现，且不会因多个同类单位叠加为不可用的噪声。对每个重要声音至少安排静态、单单位、群集和最终包四种场景。

| 场景 | 应观察 |
|---|---|
| 静态载入 | 不因扫描或缺文件产生警告 |
| 单位单次调用 | 正确事件、音量、空间和听众 |
| 快速重复操作 | 冷却/去抖后不会无限叠加 |
| 多单位战斗 | 高射速、效果链和死亡声不会压过指令反馈 |
| 地图切换 | 专属音乐与普通播放列表的切换符合策略 |
| 最终归档 | 不依赖开发机解码器、路径或旧文件 |

许可信息也应留在发布记录或资产源账本。不要仅凭“在样本模组或网络目录中找到”就认为素材可再分发。内部校验可以读取名称和依赖关系，但不能把第三方单位配置、地图或声音自动纳入自己的发布包。

### 5. locale 的内容回归

语言测试除回退外，还要检查内容与玩法一致。特别是 `displayDescription`、行动锁定消息、资源名称、地图名称和动态数值，最容易因复制后规则改变而过时。

| 文本类别 | 需要比对 | 典型回归 |
|---|---|---|
| 单位名 | 同一概念在菜单、详情、地图对象中的一致性 | 一个位置仍显示旧名 |
| 描述 | 实际攻击、费用、限制和版本范围 | 文案承诺不存在的能力 |
| 锁定消息 | `isLocked` 或资源条件 | 显示“能量不足”但真正缺的是研究点 |
| 动态状态 | 资源量、阶段、单位、词序 | 数值正确但语序或单位错误 |
| 地图 metadata | 名称、作者、缩略图描述 | 预览属于另一张地图 |
| 全局键 | `displayLocaleKey` 回退与模组自有翻译 | 在独立包中泄漏键名 |

建议做一次“反向文本审阅”：从玩家看到的每个新名词出发，找到其定义、状态规则、资源或地图对象；从每个新规则出发，找到玩家会看到的解释。这样能发现配置已改、文本未改的断层。

### 6. TMX 依赖的递归验收例程

每张 TMX 都可按递归例程处理，而无需猜测它是否“足够简单”：

1. 解析 TMX 中所有外部 `source` 和图像引用；
2. 对每个外部 TSX，解析其图像、tile 属性、对象模板或其它外部链接；
3. 计算每条相对路径的规范化根内位置；
4. 对每一项检查源树存在、归档存在、名称大小写一致；
5. 检查 TMX 中的单位/对象属性在当前模组装载后有目标；
6. 检查 metadata 缩略图与音乐目录；
7. 从最终包进入地图、重开、切换队伍和缩放；
8. 记录未能静态验证的引擎行为，例如特定自定义属性的运行时含义。

这种例程直接解释了为何 DeepStar 类样本中的“TMX + 预览 PNG + TSX”不能仅看第一层文件。预览 PNG 证明的是展示资源，TSX 证明的是图块定义的一段路径；两者都不能替代完整 TMX 依赖图或游戏内加载。

### 7. 素材变更提交模板

```text
变更：替换 signal_pylon 主体图并增加中文描述
影响：units/signal_pylon.ini；assets/images/signal_pylon.png；locale/zh.properties
图片契约：单帧、禁用队色、主体图、根内相对路径
本地化契约：默认 + zh + en；无动态表达式
验证：源目录与最终 rwmod；两个队色；远近缩放；zh/en/default 回退
地图影响：无 TMX/TSX 引用
许可：自有或已确认可发布
未覆盖：低端设备纹理压力
```

该模板刻意不包含第三方素材内容。它帮助审核者快速决定应跑哪一组测试，并在数月后仍可理解为何一个看似普通的图片或文本变更触及了这些文件。
